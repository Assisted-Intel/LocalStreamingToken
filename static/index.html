Prompt Validation & Evaluation

1. Data

Each row is one test case. Enter data by hand, or import a file. Import from a CSV (header row → columns) or a text file split into cells (blank lines by default, or your own delimiter) that fill a column you choose.

✨ Generate test data with the LLM

Describe how to fill each column and the model (from step 2) invents dummy rows to test against. The response column is left blank so an evaluation run fills it. Turn on ⚡ Parallel Processing (Settings) to fan rows across your servers.

2. Prompt

Click a column to insert its {placeholder}. Every column except the response column is available as input.

3. Grading criteria

Define how an LLM grader scores each response. Each label returns either a numeric score (within a range) or written reasoning. The grader replies as JSON that the app parses and aggregates.

The grader stays fixed across batch models so scores stay comparable.

4. Batch model testing (optional)

Add models to compare. The same prompt + grader run against each; results show a per-model score and a breakdown of how each criterion did per model. Turn on ⚡ Parallel Processing (Settings) to fan rows across your servers.

5. Run & results

Settings

Web Search API Keys

Used by the 🌐 Web search feature (Brave discovery + Bright Data page crawling). Stored in settings/settings.json (gitignored) — never committed.

AI Providers & Servers

Add Ollama servers or cloud AI providers (Claude, OpenAI, Grok, Gemini, DeepSeek, and other OpenAI-compatible services). Each cloud provider needs an API key. The built-in Local Ollama is always available.

Multi-Server Processing

Choose which servers run in parallel for the queue and batch files, and which model each uses. Each server can run a different model, or click Use common model to set them all to a model installed on every selected server. Turn it on with the ⚡ Enable Parallel Processing toggle in the chat.
