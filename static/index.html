Prompt Validation & Evaluation

1. Data

Each row is one test case. Enter data by hand, or import a file. Import from a CSV (header row → columns) or a text file split into cells (blank lines by default, or your own delimiter — optionally a regular expression) that fill a column you choose. A single-model run writes each response back into the response column.

✨ Generate test data with the LLM

Describe how to fill each column and the model (from step 2) invents dummy rows to test against. The response column is left blank so an evaluation run fills it. With ⚡ Parallel Processing (Settings) on, rows fan across every server that has the chosen model installed.

2. Prompt

Click a column to insert its {placeholder}. Every column except the response column is available as input.

3. Grading criteria

Define how an LLM grader scores each response. Each label returns either a numeric score (within a range) or written reasoning. The grader replies as JSON that the app parses and aggregates.

The grader stays fixed across batch models so scores stay comparable.

4. Batch model testing (optional)

Add models to compare. The same prompt + grader run against each; results show a per-model score and a breakdown of how each criterion did per model. With ⚡ Parallel Processing (Settings) on, each model's rows fan across its own server plus any parallel server that also has that model installed — servers without it are skipped rather than sent work that would fail.

5. Run & results

Batch Processing

1. Inputs

Each input becomes one item that your prompt runs against. Mix as many sources as you like — YouTube videos or a whole playlist, the pages behind a web search, a folder of documents (), or a folder of images, where each picture is the item your prompt describes, reads or compares.

Reference images

Optional. These are sent with every item — a style guide, a chart, or whatever each input should be compared against.

2. Prompt

Use {{content}} where the item's text should go, plus {{title}}, {{url}} and {{source}}. Leave {{content}} out and the item's text is simply added underneath.

3. Output

Saving next to the originals needs a prefix or an append value, otherwise the AI output would overwrite the files it just read.

Prompt used to name each file. {{content}} is the response it just wrote.

🧠 Memory

A memory core is what the assistant has learned about you — your preferences, the way you like to be answered, what you're working on. Enable 🧠 Memory in a chat and it grows on its own as you talk; everything it records is listed here for you to edit, add to, or delete.

Settings

Web Search API Keys

Used by the 🌐 Web search feature (Brave discovery + Bright Data page crawling). Stored in settings/settings.json (gitignored) — never committed.

AI Providers & Servers

Add Ollama servers or cloud AI providers (Claude, OpenAI, Grok, Gemini, DeepSeek, and other OpenAI-compatible services). Each cloud provider needs an API key. The built-in Local Ollama is always available.

Multi-Server Processing

Choose which servers run in parallel for the queue and batch files, and which model each uses. Each server can run a different model, or click Use common model to set them all to a model installed on every selected server. Turn it on with the ⚡ Enable Parallel Processing toggle in the chat.

General

Images

Attached images are always stored at their original resolution. This only caps the copy that is sent — an unscaled phone photo costs as much context as several pages of text without giving the model more to work with.

RAG (Retrieval Augmented Generation)

No extra embedding servers.

Database Processing

Import rows from a real database into an isolated local staging copy, edit & AI-enrich them, preview the exact write statements, then safely write back. The source is never touched until you approve.

🔒 Connection Vault

Connection settings & credentials are encrypted at rest (AES-GCM, key derived from your master password via scrypt). The password itself is never stored.
